# NairobiHot Scraper & Seeder Plan

## Overview
This document outlines the architecture and execution plan for the `nairobihot.com` scraper, designed to seed the local database with realistic locations, and services.

## Architecture
We use a two-phase architecture to separate extraction logic from ingestion logic.

1. **Extraction (Scraper)**
   - Located at: `scripts/scrapers/nairobihot.py`
   - Uses `cloudscraper` (to bypass basic Cloudflare protection) and `BeautifulSoup4` for DOM parsing.
   - Extracts a list of locations (counties and exact areas) and services.
   - Outputs the raw extracted data into `data/raw/nairobihot_data.json`.

2. **Ingestion (Seeder)**
   - Located at: `apps/models_app/management/commands/seed_nairobihot.py`
   - A custom Django Management command.
   - Reads the JSON file generated by the scraper.
   - Uses Django ORM (`get_or_create`) to safely populate the `LocationGroup`, `Location`, and `Service` models without duplicating existing records.

## Usage

**Step 1: Extract Data**
Run the scraper script directly:
```bash
python scripts/scrapers/nairobihot.py
```
This will generate `data/raw/nairobihot_data.json`.

**Step 2: Seed the Database**
Run the Django management command to ingest the data:
```bash
python manage.py seed_nairobihot
```

## Maintenance & Scaling
- The scraper is currently synchronous and single-threaded, which is sufficient for one-time or infrequent database seeding.
- If continuous scraping is required, the ingestion phase should be moved to Celery, and rotating proxies should be integrated into the extraction script to handle rate limits and IP bans.
